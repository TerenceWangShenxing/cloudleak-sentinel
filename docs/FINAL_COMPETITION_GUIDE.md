# CloudLeak Sentinel v1.0 国赛终极版使用与答辩指南

## 评分项映射
1. **公开渠道类型数量**：12 类插件，涵盖 Repo/Webhook/Wiki/URL/镜像/移动包/本地与上传。
2. **凭据类型数量**：15 类规则/组合检测器，含云厂商 AK/SK 关联。
3. **可扩展性**：SourceAdapter → Artifact 统一抽象；渠道插件与 Detector 解耦。
4. **发现数量**：去重事件、风险评分、Allowlist、历史生命周期避免“数量虚高”。
5. **发现时间**：published_at → observed_at，P50/P95+n；Git commit 和 Webhook 均支持时间戳。

## 现场“花活”但不失专业
- `✦ 战情演示`：只注入合成凭据，实时走完整检测与告警链路。
- `⌘K` 命令面板：演示系统成熟度。
- 渠道拓扑图：点击节点联动筛选。
- SSE：无需刷新实时更新指标/任务。
- 事件详情抽屉：风险证据 + 生命周期。
- 实验中心：一键重跑基准并显示规模吞吐。

## 建议 5 分钟 Demo
0:00–0:40 首页与架构；0:40–1:40 Git 历史生命周期；1:40–2:30 Docker/APK；2:30–3:30 战情演示实时注入；3:30–4:20 实验中心；4:20–5:00 安全边界与扩展性。

## 实验严谨性
Synthetic Regression 与 Curated adversarial 必须称为“合成/人工构造回归集”，不能称真实互联网准确率。Scale/latency 必须在比赛机重跑并记录环境。真正公网 Webhook E2E 时延需使用自有测试仓库进行 100 次以上授权实验。
